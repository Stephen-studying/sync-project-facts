# Source authority

Use authority to guide trace-back, not to auto-adjudicate a hard conflict.

| Level | Examples | Use |
|---|---|---|
| Raw | immutable experiment log, machine result, calculation output | Reproduce the value and conditions |
| Primary | exact configuration, dataset manifest, official team allocation record | Establish setup, scope, or explicit ownership |
| Formal | manuscript result table, signed report, maintained spreadsheet | Document a reviewed claim while checking its origin |
| Summary | PPT, README, resume, abstract | Detect communication drift and stale wording |
| Claim | unsupported prose or promotional statement | Flag proof needs; never treat as self-validating |

A raw source can still be wrong, mislabeled, or from another run. When raw and formal evidence conflict in the same scope, retain both and use `UNRESOLVED` until the run identity and conditions are verified.

Accept personal contribution only from the user's explicit confirmation, an explicit team allocation record, or a direct contribution statement in the material. Do not infer it from commit history, file metadata, authorship order, or code volume.
