## 它解决什么问题

同一个科研项目经常同时出现在多份材料中，而这些材料可能逐渐“各说各话”：

| 材料 | 说法 |
|---|---|
| 论文 | `mAP@0.5 = 93.7%` |
| 答辩 PPT | `mAP@0.5 = 94.2%` |
| README | 模块名仍是旧版本 |
| 简历 | “独立完成全部模型设计与训练” |
| 项目分工 | 只支持数据整理、标注和部分写作 |

普通对话可以指出表面差异，但 `sync-project-facts` 更适合需要**重复运行、精确溯源和保留人工裁决**的场景。它会：

1. 只读扫描同一项目的两份或以上材料；
2. 提取事实并保留行号、页码、幻灯片、单元格或键路径；
3. 先比较数据集、模态、指标定义、阈值、版本与实验条件；
4. 区分真正冲突、等价表达和合理的范围差异；
5. 生成事实总账与材料同步修复顺序。

> 一句话理解：它不是“润色助手”，而是科研材料发布前的**事实一致性审计器**。

## 适合什么时候用

- 保研、求职或答辩前，核对简历、项目介绍和 PPT；
- 投稿或返修前，核对论文正文、表格、补充材料和实验记录；
- 项目版本迭代后，找出仍在使用旧指标、旧模块名或旧结论的材料；
- 团队协作时，审计个人贡献与团队分工是否有证据支持；
- 长期维护同一项目，需要二次运行仍保留已确认裁决。

如果只有一两份很短的材料，而且只比较一次，直接让普通 AI 对话核对通常更省事；当材料多、风险高、需要复查或自动化时，再使用完整审计流程。

## 核心能力

### 多格式证据抽取

支持 Markdown、TXT、代码、JSON、YAML、CSV、DOCX、PPTX、XLSX 和 PDF。根据格式尽量保留精确定位：

- 文本与代码：行号
- PDF：页码
- DOCX：标题、段落或表格位置
- PPTX：幻灯片与文本框
- XLSX：工作表与单元格
- JSON / YAML：键路径
- CSV：行号与列名

### 八类事实状态

| 状态 | 含义 |
|---|---|
| `CONSISTENT` | 同一事实、同一范围完全一致 |
| `EQUIVALENT` | 百分比、小数、单位、舍入或别名可证明等价 |
| `SCOPED_DIFFERENCE` | 因模态、数据集、版本、阈值或指标定义不同而合理不同 |
| `STALE` | 材料仍使用已被明确取代的旧事实 |
| `CONTRADICTED` | 同一范围出现不可兼容的值 |
| `UNSUPPORTED` | 有主张，但没有可追溯证据 |
| `MISSING` | 用户明确要求同步的事实在目标材料中缺失 |
| `UNRESOLVED` | 有冲突，但现有证据不足以裁决 |

个人贡献冲突会标记为 `OWNERSHIP`，严重度不低于 `High`。

### 审慎裁决

本技能 不会因为“多数文件都这样写”、文件更新时间更晚，或某个指标更高，就自动认定其为事实。硬冲突会保留全部候选值及来源，等待用户裁决；已经人工确认的决定在后续运行中不会被静默覆盖。

## 运行结果

一次完整运行至少生成：

```text
run/
├── project-facts.json     # 规范化事实总账
└── fact-sync-report.md    # 可读的同步审计报告
```

报告包含材料清单、规范化事实总账、冲突矩阵、高风险问题、建议修复顺序、未决问题与各材料同步状态。可以直接查看仓库中的 [PV-YOLO 合成示例](examples/pv-yolo-project/output/fact-sync-report.md)。

## 开始使用

### 1. 安装

将仓库克隆或下载到 Codex 的技能目录：

```powershell
git clone https://github.com/Stephen-studying/sync-project-facts.git `
  "$env:USERPROFILE\.codex\skills\sync-project-facts"
```

技能的核心流程默认离线运行。Python 3.10+ 即可处理文本、代码、JSON、CSV 及常见 Office Open XML 文件；PDF 或 YAML 的增强抽取可按需安装相应轻量依赖，缺失时会给出清晰警告。

### 2. 在 Codex 中调用

```text
使用 $sync-project-facts 只读对比这个项目的简历、论文、PPT 和实验结果，
建立带精确来源的事实总账，列出冲突、未决项和建议修复顺序。
不要修改原文件，也不要自动选择更高的指标。
```

更完整的执行约束和命令见 [SKILL.md](SKILL.md)。

## 可选的本地偏好记忆

新版增加了一个**本地、可控、与项目事实隔离**的偏好记忆层：

- 记住“回答简洁一点”“使用表格”“先给结论”“使用中文”等明确反馈；
- 记录精简的问答摘要，在后续会话中避免重复已被否定的回答方式；
- 模糊推断不会自动生效，必须由用户确认；
- 当前请求始终优先于历史偏好；
- 历史回答永远不能作为项目事实证据。

记忆默认保存在 `.local-memory/`，已被 Git 忽略，不会随仓库上传。用户可以查看、删除单项偏好或完全重置。详细规则见 [本地记忆说明](references/local-memory.md)。

## 工作流程

> **① 材料扫描** → **② 证据定位** → **③ 事实核对** → **④ 人工裁决** → **⑤ 输出结果**
>
> 只读计算哈希 · 保留精确位置 · 区分冲突与范围差异 · 不静默覆盖 · 生成事实总账与同步报告

## 隐私与安全边界

- 默认本地处理，不上传源材料，不依赖外部网络；
- 所有源材料只读，MVP 只生成修复建议；
- 不编造实验结果、部署状态、开源状态或个人贡献；
- 不把旧回答、用户偏好或文件修改时间当作事实证据；
- 不用于单文档润色、翻译、答辩题生成、数据集质量检查、文件筛选或技术路线绘制。

## 验证状态

当前测试覆盖：

- 旧模块名、无证据提升、个人贡献冲突；
- 中文路径、源文件哈希不变、二次运行幂等；
- JSON Schema、精确来源定位、离线核心流程；
- 本地偏好学习、模糊反馈待确认、跨会话摘要召回与清除。
